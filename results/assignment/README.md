# Group 25: Noise Schedule Ablation in Diffusion Models (DiffWater, EUVP)

Foundation Models and Generative AI group assignment. We fine-tune a pretrained underwater-enhancement diffusion model under its original noise schedule θₜ (Run A) and under θₜˣ with x = 2.00 (Run B), and compare both with the pretrained model without fine-tuning (Run 0). The write-up is `report/Report.md`. This file says what is where and how to reproduce every run.

## Read this first: DiffWater, not UW-DiffPhys

The Phase 1 declaration names **UW-DiffPhys**, and the git repository around this folder is a clone of it. **None of the runs uses UW-DiffPhys code.** They use **DiffWater** (`Guan-MS/DiffWater`), cloned fresh into Colab. We switched because the UW-DiffPhys checkpoint sits on a restricted Google Drive we cannot open, and training it from scratch on a Colab T4 was not feasible. ## Results in three lines

30 held-out EUVP Underwater Dark pairs, output vs reference. All three runs use the same images, sampler and per-image seeds.

| | PSNR (dB) | SSIM |
|---|---|---|
| Input (colour-compensated), no model | 20.65 | 0.889 |
| Run 0, pretrained | 16.91 ± 3.07 | 0.792 ± 0.071 |
| Run A, fine-tuned, θₜ | 14.36 ± 3.02 | 0.770 ± 0.112 |
| Run B, fine-tuned, θₜ², x = 2.00 | 12.85 ± 2.19 | 0.763 ± 0.097 |

- Run B minus Run A: **−1.51 dB PSNR** (standard error 0.40, A higher on 25 of 30 images); SSIM difference −0.007 (s.e. 0.008), not distinguishable from zero.
- Fine-tuning itself lowered PSNR against Run 0 (A − Run 0: −2.55 dB, s.e. 0.53).
- One seed, one exponent, 30 images. Read `report/Report.md` for the analysis and the limits. Per-image numbers and all paired tests: `experiment/RESULTS.md`.

## How to reproduce

All steps run in Colab on a T4 (Runtime > Change runtime type > T4 GPU), using `RunAB_Finetune_Guide_v3.ipynb`. Run its cells one at a time, in the order below, and **do not use "Run all"**.

### 1. Setup (notebook Step 0)
- Mount Drive. Paths used: outputs in `My Drive/FoundationModel-Assignment/`, checkpoint in `My Drive/DW/LSUI/I390000_E78_gen.pth`.
- Each Google account needs its **own copy of the checkpoint**: open the authors' folder (link above), right-click `LSUI/I390000_E78_gen.pth`, Make a copy, move the copy to `My Drive/DW/LSUI/`. (Copying works for files, not folders.)
- Upload `finetune.py` to `/content` (left sidebar). Check its md5 is `38c97203e8ccafdfb80cb2be74b0bb3a`.
- The notebook clones DiffWater and installs the packages. To pin the version exactly, after cloning run:
  ```
  git -C /content/DiffWater checkout 7db68f34060bbf1d7c5b8153664fb16a3dcda1ae
  pip -q install tensorboardX scikit-image lmdb pyyaml kagglehub pandas
  ```

### 2. Build the data (notebook Step 3, the cell that starts `from PIL import Image`)
This cell downloads EUVP, indexes every pair by MD5 and a perceptual hash, draws the 30 test pairs, removes exact and near duplicates of them from the training pool, draws 800 training pairs, and writes 256 × 256 PNGs to `/content/euvp_test` and `/content/euvp_train`. It is seeded (1234), so every session builds the same split. **Check these printed values; they must match in every account:**

| What | Expected |
|---|---|
| `split fingerprint` | `f8cc4714a30c` (also `test split identical to the one saved on Drive`; the very first time in a new account it says `saved test split to ...` instead) |
| train pairs / fingerprint (the cell below Step 3) | 800 pairs (575 Dark + 225 Scenes), `train fingerprint: 6a9f33de995c` |
| duplicates removed from the training pool | 5 exact, 0 near |

There is no standalone script for this step; it exists only as that notebook cell.

### 3. The three runs
The launch cell of the notebook builds and runs exactly these commands (it prints the command it runs). Run A and Run B use the same command except `--run` and `--out_dir`. Learning rate 1e-5 and seed 1234 are the script defaults; add `--lr 1e-5 --seed 1234` to make them explicit.

```bash
# Run A: fine-tune with the original schedule
python -u /content/finetune.py --run A \
  --repo_dir /content/DiffWater/DiffWater \
  --ckpt_prefix /content/drive/MyDrive/DW/LSUI/I390000_E78 \
  --train_root /content/euvp_train --eval_root /content/euvp_test \
  --out_dir /content/drive/MyDrive/FoundationModel-Assignment/runs/RunA \
  --epochs 10 --batch_size 4 --n_eval 30 --n_samples 3

# Run B: the same, with the schedule raised to the power X = 2.00 (set at the top of finetune.py)
python -u /content/finetune.py --run B \
  --repo_dir /content/DiffWater/DiffWater \
  --ckpt_prefix /content/drive/MyDrive/DW/LSUI/I390000_E78 \
  --train_root /content/euvp_train --eval_root /content/euvp_test \
  --out_dir /content/drive/MyDrive/FoundationModel-Assignment/runs/RunB \
  --epochs 10 --batch_size 4 --n_eval 30 --n_samples 3

# Run 0: pretrained weights, no training, same sampler and seeds, original schedule
python -u /content/finetune.py --run 0 \
  --repo_dir /content/DiffWater/DiffWater \
  --ckpt_prefix /content/drive/MyDrive/DW/LSUI/I390000_E78 \
  --eval_root /content/euvp_test \
  --out_dir /content/drive/MyDrive/FoundationModel-Assignment/runs/Run0 \
  --epochs 10 --batch_size 4 --n_eval 30 --n_samples 3     # epochs, batch_size, n_samples are unused by Run 0
```

Optional checks that were run before the real runs: `python finetune.py --benchmark ...` (speed and memory per batch size; batch 4 chosen) and `python finetune.py --smoke --run B ...` (a two-minute test of the code path).

**Keep the browser tab open and the laptop awake while a run is going.** A Colab session with no running cell is disconnected, which cost Run A its first session. The notebook's launch cell is a blocking call for this reason.

### 4. What a healthy run prints
- First lines: `run=B exponent=2.0 ...`, then `schedule OK: ...`. **Run A and Run 0 must say `exponent 1.0`, `abar_last 4.386e-05`, `beta_max 0.01`. Run B must say `exponent 2.0`, `abar_last 1.924e-09`, `beta_max 0.0199`.** The run asserts this after every checkpoint load.
- Training: 200 steps per epoch at about 1.3 to 1.4 s/step (about 4.5 min per epoch). At epochs 2, 4, 6, 8, 10 it writes 3 sample images (about 5.3 min each).
- End: `FINAL  PSNR ... SSIM ... over 30 images`, then `ALL DONE`.
- Run times on a T4: Run 0 about 162 min; Run A and Run B about 4.5 h each (training 45 min, epoch samples about 65 min, final evaluation about 145 min).
- Numbers we obtained (a rerun will differ slightly because of GPU non-determinism): Run 0 16.908 dB / 0.7925, Run A 14.360 dB / 0.7701, Run B 12.849 dB / 0.7631.

### 5. If Colab disconnects
Reconnect **in the same Google account**, run the setup cells and Step 3 again, then the launch cell with the same `RUN`. `finetune.py` resumes from `out_dir/resume.pt` (saved at epochs 2, 4, 6, 8, 10) and skips every image already written. The first lines should say `resumed from epoch N`. If they instead start at `epoch 1`, stop at once: it did not find `resume.pt`.

### 6. What each run writes (in `out_dir`)
`run.log`, `run_config.json`, `train_log.csv` (columns `epoch, train_loss`; Runs A and B only), `train_steps.csv`, `samples/epoch_02 … epoch_10/` (per test image k: `idxKK_input.png`, `idxKK_output.png`, `idxKK_target.png`, `idxKK_traj.png`, plus `metrics.csv`), `final_eval/` (the same files for all 30 images), `eval_metrics.csv` (per-image PSNR and SSIM), `resume.pt` (1.74 GB) and `final_gen.pth` (593 MB, the fine-tuned weights; Runs A and B). Run 0 writes only `run.log`, `run_config.json`, `final_eval/` and `eval_metrics.csv`.

- `idxKK_input.png` is the colour-compensated input (the repository's loader applies that), not the raw image.
- `idxKK_traj.png` is a strip of five 256 × 256 panels: the noisy sample x_t at t = 1999, 1499, 1000, 500 and the final x₀ (t = 0).
- Metrics: scikit-image PSNR and SSIM, `data_range=255`, `channel_axis=2`, output vs reference. The repository's own `eval.py` is not used; it compares the input with the target.

## How the code is organised
- `finetune.py` imports the unmodified DiffWater code and replaces **one method** at run time, `GaussianDiffusion.set_new_noise_schedule` (`model/ddpm_modules/diffusion.py`, lines 106 onward), with a copy whose only changes are the five lines marked `# MODIFIED` (lines 86, 87, 89, 90, 91: the exponent and the per-step coefficients re-derived from it) plus the line that installs the replacement (line 289). No DiffWater file is edited on disk. Everything else in `finetune.py` is `# ADDED`.
- **The schedule buffers are stored inside the checkpoint.** Loading the pretrained checkpoint overwrites any modified schedule with the original. `finetune.py` therefore re-applies the schedule after every load and asserts that it equals ᾱₜ^exponent. Notebook Step 5 demonstrates the problem.
- The exponent is the named constant `X = 2.00` at line 46. Run A and Run 0 always use exponent 1.

## How the work is documented
`experiment/PROTOCOL.md` defines the format: one file per run with machine-readable front matter, an append-only log, decisions in `DECISIONS.md`, and `experiment/collate.py` (standard library only) that checks every run against the frozen settings in `EXPERIMENT.md` and writes `RESULTS.md`. Regenerate it with `python3 experiment/collate.py`. Regenerate the report figures and tables with `python3 -I report/make_figures.py`.

**Deviations from an uninterrupted run** (details in `experiment/RunA.md`): Run A ran in four Colab sessions. Its first session trained epochs 1 to 10, but the last resume file did not reach Drive, so session 2 resumed from epoch 8 and trained epochs 9 and 10 again (epoch 9 loss 0.06070 both times). Test images 25 to 30 were sampled in two further sessions, in two other Google accounts, resuming from the same epoch-10 file. Settings, script, commit and data fingerprints were identical in every session. Runs 0 and B ran in one session each.
